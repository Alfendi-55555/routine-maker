## 4. 사용법

> 초안입니다. 배포된 화면을 보면서 본인 말로 다듬어 주세요.

1. **주간 틀**에서 수업·통학·알바처럼 매주 반복되는 고정 일정을 넣습니다. 고정 일정 앞뒤 전환 시간(기본 10분)을 뺀 나머지가 빈 시간이 됩니다.
2. **루틴**에서 루틴을 만듭니다. 무엇을 할지, 주 몇 번 할지, 기본/최소 시간을 정합니다. 언제 시작할지(앵커)와 무엇으로 셀지도 함께 정합니다.
3. **오늘**에서 할 루틴과 빈 시간을 확인하고, 기본 또는 최소 버전으로 시작합니다. 새로고침하거나 탭을 닫아도 타이머는 시작 시각부터 이어집니다.
4. 끝나면 **끝냈어요**를 누릅니다. 분량이 매번 다른 루틴은 이때 분량(예: 슬라이드 장수)을 입력합니다.
5. 기록이 3개 쌓이면 예상 시간이 보정되고, 10개가 쌓이면 **돌아보기**에서 걸린 시간과 시작까지 걸린 시간의 변화를 볼 수 있습니다.

- 반복하지 않는 일은 오늘 탭의 **한 번만 하는 일**에서 재거나 직접 입력합니다.
- **캘린더** 탭에서 공휴일과 기록한 날을 달력으로 보고, 날짜를 누르면 그날 고정 일정과 기록을 볼 수 있습니다. 공휴일에 쉬는 고정 일정 종류도 여기서 정합니다.
- 오늘 탭 맨 위 **지금** 카드가 지금 남은 시간에 들어가는 루틴을 보여 줍니다. 돌아보기의 **규칙 다듬기 제안**으로 횟수·기본 시간을 기록에 맞게 고칠 수 있습니다. 기록은 나중에 고치거나, 지운 직후 되돌릴 수 있습니다.
- 화면이 비어 있을 때는 돌아보기 › 기록 관리의 **예시 데이터로 둘러보기**로 5주치 예시를 넣어 볼 수 있습니다.

## 5. 데이터 출처와 갱신일

| 데이터 | 출처 | 갱신 | 쓰는 곳 |
|---|---|---|---|
| 공휴일 | [한국천문연구원 특일 정보](https://www.data.go.kr/data/15012690/openapi.do) (공공데이터포털) | 매달 1일 GitHub Actions가 받아서 `data/holidays.json`에 저장. 마지막 갱신일은 앱의 캘린더 › 공휴일 설정에 표시 | 공휴일에는 수업·통학 같은 고정 일정을 빼고 빈 시간을 계산 |
| 사용자 기록 | 사용자가 직접 입력 | 입력할 때마다 | 브라우저 `localStorage`(키 `routinemaker.v1`)에만 저장 |

- 인증키는 GitHub Secrets(`DATA_GO_KR_KEY`)에만 두고 GitHub Actions에서만 씁니다. 앱(브라우저)은 저장소에 커밋된 `data/holidays.json`만 읽으므로 키가 공개되지 않습니다.
- 서버 전송, 로그인, 외부 글꼴·분석 도구 없음.
- 문서 갱신일: 2026-10-16

## 개발자용

- 구조: `index.html`, `style.css`, `js/calc.js`(계산), `js/store.js`(저장), `js/sample.js`(예시 데이터), `js/app.js`(화면)
- 빌드 도구·외부 라이브러리 없음. `index.html`을 더블클릭해도 동작합니다.
- 계산 테스트: `node --test tests/`
- GitHub Pages: 저장소 Settings → Pages → Branch `main`, 폴더 `/ (root)` → Save
- 공휴일 데이터 설정
  1. [공공데이터포털](https://www.data.go.kr/data/15012690/openapi.do)에서 "한국천문연구원_특일 정보" 활용 신청 → 마이페이지에서 **일반 인증키(Decoding)** 복사
  2. 저장소 Settings → Secrets and variables → Actions → New repository secret: 이름 `DATA_GO_KR_KEY`, 값은 위 키
  3. Actions 탭 → "공휴일 갱신" → Run workflow (처음 한 번). 이후 매달 1일 자동 실행
  - 로컬에서 직접 받기: `DATA_GO_KR_KEY=<키> node scripts/fetch-holidays.js`
  - 파일로 연 `index.html`에서는 브라우저 보안 때문에 공휴일 파일을 못 읽습니다. 배포된 주소나 로컬 서버에서 확인하세요.
